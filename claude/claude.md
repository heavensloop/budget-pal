# when implementing a feature:
- always create a feature branch, never commit directly to main
- Always ask me questions about implementation of trickier features before writing code
- Never assume you know what I want, always ask me questions first
- Write clean, maintainable/testable code
- Always write tests for your code
- Use semantic commit messages, e.g. `feat: add new feature`, `fix: fix a bug`, `refactor: remove user reference code`, `test: add more test-cases for incoming items`, `docs: update internal documentation for budget items`, `chore: update dependencies`, etc.
- It's ok to add commit descriptions for more complex commits, but keep them concise and to the point
- When asked to give a PR description in markdown (code) so I can copy/paste, always use the PR template. Do not include changed files or code snippets as the code would be reviewed eventually. Instead, describe the changes in words and why they were made. If you need to include code snippets, use a code block and keep it concise.
- When I ask you to fix something or make a change/update, always ask me before committing the change. I want to be involved in the decision-making process and understand the reasoning behind the change. Also ask me which branch to commit the change to, and whether to create a new branch or commit to an existing one. Always ask me if I want to review the code before committing it.
